# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

huckepack is a website that collects and visualises data about official long-distance hiking trails worldwide, focused on well-known thru-hiking routes: one page per trail plus comparisons across trails. docs/scope.md holds decisions and open questions (record new decisions there), docs/data-sources.md lists sources with their licences, docs/roadmap.md ranks candidate trails and features (update it when one is built).

## Commands

```bash
npm install          # once (inside Claude Code's sandbox: npm_config_cache="$TMPDIR/npm-cache" npm install)
npm run dev          # local site at http://localhost:4321; runs detached (npx astro dev status | logs | stop)
                     # before starting: lsof -nP -iTCP:4321 -sTCP:LISTEN; if one is running, reuse it (it reloads
                     # on file changes). Claude Code's sandbox can't stop a detached server; the user has to.
                     # After changing `src/content.config.ts` (delete `.astro/data-store.json` first, or the restarted server reuses stale content) or adding an npm dependency, the server must be restarted: a running server serves
                     # the new package as "504 outdated dependency" and the page breaks.
                     # Dev errors (e.g. a bare "FailedToLoadModuleSSR" page) are logged in .astro/dev.log. Create a new
                     # component file before importing it; if an import failed meanwhile, touch the importing file.
npm run build        # dist/: the static site; fails if a trail file doesn't match the schema
npm run check        # type check (Astro, Svelte, TypeScript)

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # once (PyYAML, truststore)
.venv/bin/python -m pipeline.routes <slug>             # map line: OSM ways matched to the stages' tracks (cached in data/raw/<slug>/)
.venv/bin/python -m pipeline.routes <slug> --refresh   # download tracks and OSM ways again
.venv/bin/python -m pipeline.water <slug>              # drinking water and springs near the route (after routes)
.venv/bin/python -m pipeline.surface <slug>            # surface categories along the route (after routes)
.venv/bin/python -m pipeline.elevation <slug>          # elevation profile (after routes; Copernicus GLO-30 tiles, downloaded once into git-ignored data/dem/)
.venv/bin/python -m pipeline.access <slug>             # road distance from the record's travel hubs to the start (OSRM)
.venv/bin/python -m pipeline.climate <slug>            # climate by month at the lowest and highest point, daylight (after elevation; ERA5 via Open-Meteo)
```

Inside Claude Code's sandbox, pip needs `PIP_CACHE_DIR="$TMPDIR/pip-cache"`. Python downloads verify certificates through the OS trust store (`truststore`); never disable verification.

## Architecture

- `data/trails/<slug>.yaml`: the trail database, one file per trail; the file name is the URL slug. `src/content.config.ts` is its schema (Zod): every figure names a `source` id from the trail's `sources`, and the build fails on an unknown id. A source's `retrieved: null` means its figures are not yet checked; the page says "not yet verified". `notes` holds discrepancies between sources and open questions; they are for us, not shown on the page.
- `src/lib/trails.ts`: derived figures, never stored: totals from the main stages (`kind: main`; approaches and variants are excluded), averages per day (only when days and stages share a source), and the SAC grade for filtering (stated; converted from CAI with `CAI_TO_SAC`; or, when no grade is published, our estimate in the record's `difficulty.estimated` with a `basis` sentence from the source's description, shown in the popover). Every place that explains the grade says `SAC_NOTE`: grades are translated into the SAC scale to compare trails, but stay an estimate. Each result carries its source.
- `pipeline/`: Python, downloads and processes source data into `data/raw/<trail>/` (committed cache, with `manifest.json` retrieval times; official GPX tracks are copyrighted and git-ignored, so a fresh clone needs `--refresh` once; never commit them, the repo is public) and writes derived data. The site build never downloads. `pipeline/routes.py` builds `public/routes/<slug>.geojson`: one simplified LineString per stage (number, kind, coverage) of OpenStreetMap geometry, matched by `pipeline/osm.py` to the stage's `track` (GPX). The matcher fetches OSM ways within 200 m of the track (Overpass, cached as `osm-stage-*.json`) and takes the cheapest path from start to end, where a way costs its length × (1 + (distance from track / 15 m)²). The GPX only guides the choice; none of its geometry is published. Trails without GPX (Laugavegur) set `route.relation` (the OSM hiking relation) and an `end` point per stage: the relation's main ways (plus `route.alternatives`, ways with role alternative that close gaps) are chained from the start into one line, cut at the stage ends, and each piece guides the matcher like a track (`relation_line`, `split_at`; a jump over `MAX_RELATION_GAP_M` ends the chain and the leftover ways are reported). The printed report flags stages where less than 95% of the track is within 30 m of the result: usually OSM is missing a path there; record it in the trail's `notes`.
- `data/derived/<slug>.json`: data the pipeline derives for a trail, never edited by hand; the `derived` collection in `src/content.config.ts`. `water` (from `pipeline/water.py`): OSM drinking water (amenity=drinking_water/water_point, man_made=water_tap, springs tagged drinking_water=yes) and other springs within 250 m of the route, each with its stage and km along the main route (measured on the map line), counts per stage, and the longest stretches without drinking water / any water. Its `source` must be an id in the trail's `sources` (`osm`). A record can add drinking water a source names that OSM lacks (`waterPoints`, e.g. FÍ's hut taps on the Laugavegur): those points carry their own `source`, OSM drinking water within 100 m of one is the same tap and dropped, the derived `extraSources` lists them, and the chart caption and explanation name them. `access` (from `pipeline/access.py`): for each hub in the record's `access` list (the nearest major hubs only: a main railway station, or where there is no railway the main bus station the trail's buses leave from (`kind: bus`, e.g. Reykjavík BSÍ), and international airports, no small local stations; chosen by hand, coordinates from OSM; no notes), the road distance and driving time to the start from the public OSRM demo server (light use only; source `osrm`) and the straight-line distance.
- Sleeping: records list types (`SLEEPING_TYPES`); pages and the search filter group them into `SLEEPING_CATEGORIES` in `src/lib/trails.ts`, in this order: wild camping (from the record's `wildCamping`, no types), camping, huts, hostels, rooms. Category labels must fit one line in a fifth of the page width (the sleeping strip has five columns), so keep them short. Every type belongs to exactly one category; add new types to a category there. `SLEEPING_LABELS` are generic and in sentence case; local names (rifugi, refugios) belong in a trail's own text.
- Elevation (`pipeline/elevation.py`): samples the main stages every 100 m on the map line (same kilometres as water and surfaces), heights from the Copernicus DEM GLO-30 (30 m grid, source `copdem`): its 1° GeoTIFF tiles come from AWS Open Data (no account) into git-ignored `data/dem/` (30–45 MB each, shared by all trails), read with rasterio and interpolated bilinearly; the sampled heights are cached in `data/raw/<slug>/elevation-glo30.json`. It is a surface model, so in forests it measures the treetops. Its licence requires the notice in the source record ("produced using Copernicus WorldDEM-30 …") and the liability disclaimer in the legal notice; keep both. National lidar models (Saxony DGM1, Czech DMR 5G) are candidates in docs/data-sources.md, not in use: one profile must not mix terrain models. After rerunning this step, rerun pipeline.climate (its places are the highest and lowest point). The page shows highest/lowest point and start → finish, and an area profile (accent colour) with the peak labelled, gridlines and a crosshair tooltip. Its heights come from the terrain model and are not mixed with the stated stage elevations or ascent.
- Surfaces (`pipeline/surface.py`): `pipeline/routes.py` records which OSM ways each stage uses (`routeWays` in the derived file); the surface step downloads their tags and sorts them into natural ground, gravel, paved (surface tag first; ways tagged only `unpaved` or untagged are inferred from the way type: footpaths natural, tracks and roads gravel; the inferred share is reported and shown) or unknown. Runs are placed on the same map-line kilometres as water (each stage scaled to its simplified length), so the charts line up. The page shows the share of each category and a bar along the main route with a hover/tap tooltip; colours `--surface-*` in `Base.astro`, fixed order natural (teal), gravel (amber), paved (asphalt grey, by request). Checked with the dataviz validator in light and dark mode: separation passes for normal and colour-blind vision; the grey fails the chroma floor by design and differs by lightness (darker than teal and amber in light mode, lighter in dark mode), and every category is named in text, so keep that when changing them.
- Steepness: `gradients()` in `src/lib/trails.ts` derives it from the elevation profile at build time (no pipeline step), in walking direction and within each stage only: consecutive stages on the map line can be hundreds of metres apart, and a gradient across that jump is fake. Bars are 200 m, the steepest climb and descent the steepest 500 m, steep means ≥ 15 % (`STEEP_PERCENT`). The page shows both steepest stretches ("Steepest climb/descent · stage n"): the slope glyph at its true angle on the left, beside the gradient and degrees, with the metres over 500 m beneath; on phones the steep kilometres take a row of their own, the km steeper than 15 % up and down, and a gradient chart: climbs above the zero line, descents below, on the same km as the other charts. Colours `--grade-*`, a diverging scale (climbs warm, descents violet, a moderate and a steep step each; no neutral midpoint, since level ground has no bar), checked with the dataviz validator in both modes.
- Climate (`pipeline/climate.py`): 30 years (1995–2024) of daily ERA5 weather from the Open-Meteo historical API at the trail's lowest and highest point (coordinates from the elevation step), adjusted to their elevation, averaged per month (day high, night low, wet days ≥ 1 mm, snow days ≥ 1 cm, frost nights, precipitation); daylight is computed for the 15th of each month. Source id `era5`. The page shows season ranges (day highs low down, night lows up high, wet days, daylight) and one chart in three panels over twelve month columns, each panel with its own scale: temperature range bars for both places (`--clim-low`, `--clim-high`), wet days at the high point with snow days as their lower segment (`--wet`, `--snow`), and daylight as a filled share of 24 h (`--daylight`, a strong yellow; in light mode below 3:1 on cream, so every pill keeps its printed value); the two places are named "lowest point" and "highest point" everywhere (strip, legend, tooltip, table), without their heights; the record's season months are shaded. Hover or tap a month for all its figures; a screen-reader table carries the same numbers.
- Water: availability (`WATER_LEVELS`: frequent ≤ 10 km, regular ≤ 20 km, scarce beyond, by the longest stretch without drinking water). The page shows three figures (drinking water points, springs, longest dry stretch with its rating) and a strip chart of the main route: drinking water as filled `--water` dots, springs hollow, stage starts as ticks (`water.stageStarts`), the longest dry stretch as a shaded band; each dot shows a tooltip on hover or tap (a small script in the trail page; one `.tip` element per chart; Esc or a tap elsewhere closes it); stage labels sit centred on each stage's stretch, the 0 km and total km on a line below; the chart has a text summary as its accessible name. Chart kilometres are on the map line and cover the main route only; the counts include approach and variant.
- Icons: `src/components/Icon.astro` inlines Lucide icons (`lucide-static`, ISC) as SVG at build time, decorative unless given a `label`. Used for travel hubs (train/plane, labelled) and home page features only. Key figures, sleeping labels and stage figures carry no icons: words, units and arrows (m ↑, m ↓) say what a number is, and fewer marks keep the page calm. New icons: import the SVG in `Icon.astro` and add it to `ICONS`.
- Key figures, sleeping and water share one design: a strip (`.strip`: a rule in text colour on top, hairlines between items, no filled boxes). Figures are value first, large serif number with a small unit, label small beneath (the Season key figure shows the search cards' month cells in two rows of six instead of a number, as tall as the numbers beside it, with the record's wording for screen readers) (`dt` before `dd` in the markup, reordered by CSS). Status is a shape plus a word (`STATUS` in the trail page: full = available/allowed/frequent, half = restricted/regular, crossed = prohibited/scarce, empty = none listed); the colour tokens `--good/--fair/--poor` only fill the shape, text stays in text colours. The wild camping rule follows the sleeping strip, led by the same mark. Location is one grid of label-over-value items (`.loc`, 4 columns on desktop, 2 on phones; `.wide` items span 2), so rows always align whatever the content; it reads start, finish, travel hubs, country, regions, protected areas, waymarking, route type, managed by (route type sits there, not in the key figures, and fills the last row). Long values get `.wide`. Stages are a timeline with figures in aligned columns, one line per stage from 820 px, under a quiet text header (Distance, Ascent, Descent, Elevation, Time; column widths in rem so header and figures line up; Elevation and Time only when some stage has them, with an empty cell for a stage that lacks one). Stage ascent and descent are optional in the record (some sources give neither); `stageTotals()` sums them only when every main stage has them. A stage time can be a range (`minutes` to `maxMinutes`, shown "4–5 h"). Where the source gives no stage heights, climbs or times, `stageEstimates()` in `src/lib/trails.ts` fills them: heights from the elevation profile at each main stage's first and last sample, ascent and descent as the sum of the climbs and drops between its 100 m samples (all to 10 m; the key figures then show the summed estimate as "≈ … (estimate)"), times by DIN 33466 (`walkingMinutes()`) from the stage's own stated distance, ascent and descent, so a time never mixes sources. Estimates are muted and marked ≈ (screen readers hear "estimated"), the note under the table names the methods, and published figures are never replaced; narrower screens drop the header and rely on units and arrows. The map shows only the route and termini. Keep the page compact: sections 36 px apart, map 11:5 on desktop. From 1080 px, section headings sit in a left margin column (136 px, floated) and each section's content is indented 160 px beside its title, like a printed guidebook: it separates sections without rules or bands and saves the heading rows. Narrower screens stack as before; the 1080 px breakpoint keeps the content column at least 820 px wide (one-line stage timeline, five sleeping columns). Key figures and map (hidden headings) keep the full width. Phones (below 640 px): every chart svg sits in a `.chart-scroll` strip that scrolls sideways at a readable 800 px (labels 13 px), while legends and captions stay put; `.spec.three` strips put the third figure on its own row (steepness: one per row); sleeping shows wild camping across the top and the four bed categories in two columns. Touch screens (`pointer: coarse`) get taller filter chips and segmented buttons and 26 px slider thumbs. No page may scroll sideways: screen-reader tables go inside a `div.sr-only` (a table ignores the 1 px width of `.sr-only`), and `.spec.cols` strips keep two columns on phones. Colours in `Base.astro` (including `--water`) were checked for WCAG AA in both modes; check new ones too.
- Explanations: `src/components/Explain.astro` makes a label itself the button (`term`, dotted underline, no "?" icon) that opens a popover (`popover` attribute, no JavaScript; closes with Esc, a click outside or Close); the slot holds the text. With `shared`, it renders only the term and opens another Explain's popover of that id (two labels, one text: the steepest climb and descent share "Gradient", which explains %, metres and degrees with a reference table). Used for the SAC scale on the difficulty key figure (`SAC_SCALE`), the steepness figures and for every sleeping and water card (sleeping texts are the `hint` of each `SLEEPING_CATEGORIES` entry). Strips show no hint lines; explanations live in the popovers. `src/components/Explain.svelte` is the same for Svelte islands (the search filters); keep the two in step. Figure captions are one short source line; no "hover or tap" instructions (the dotted terms and cursors make interaction discoverable).
- Trail page: an on-page navigation (sticky, on a `--surface` band, links in text colour) links to the sections the trail has; a small script underlines the section in view in the accent colour (`aria-current="location"`) and keeps it visible in the phone row. The page shows no footnote markers: figures are not linked to their source on the page; the Sources section lists every source of the record with its licence (retrieval dates stay in the record, not on the page; an unchecked source shows "not yet verified"). The record still names a source for every figure.
- Maps: `src/components/TrailMap.svelte` (MapLibre GL, `client:visible`) draws the route over an OpenFreeMap basemap (OpenStreetMap data, no API key) that follows the site theme: "liberty" in light mode, "dark" in dark mode, switched live when the theme changes (`setStyle` drops custom layers, so everything is added again on `style.load`; route and termini colours come from the theme tokens). On top: hill shading and contour lines (labelled on major lines from z12; spacing per zoom in `CONTOURS`) from AWS Terrain Tiles (Terrarium PNGs on s3.amazonaws.com, no key), decoded by `maplibre-contour` in its own worker; terrain sits under water, roads, buildings and labels; main stages solid, approaches and variants dashed, start and end as dots. The trail page passes the route only if `route` is set and the file exists; otherwise the map shows just the termini. The attribution names the route's source.
- `route.publishable: false` means the geometry's licence doesn't allow republishing it (official GPX tracks usually don't). Such routes are fine for local work but must not be deployed: replace them with OSM-derived geometry first. `data/raw/` may hold such files too; never copy them into `public/` other than through the pipeline.
- Logo: the 8 × 8 pixel cairn (each stone carried huckepack by the one below). `design/logos/make.py` holds all proposals and writes the chosen one (`FINAL`) to `src/assets/logo.svg` (currentColor; the header shows it at 24 px in the accent colour, a whole multiple of 8 so the pixels stay crisp) and `public/favicon.svg` (plain colours), plus PNGs at whole-number scales of the grid (`apple-touch-icon.png` 180 px on cream, `favicon-32.png` transparent fallback, `icon-512.png` on cream), written with the standard library. Edit the grid there and rerun it; don't edit the outputs.
- Theme: `src/components/ThemeToggle.astro` in the header switches auto (system setting, default) / light / dark, stored in localStorage `theme` and applied as `<html data-theme>`; an inline script in `Base.astro`'s head applies a saved choice before the first paint. Dark tokens live under `:root[data-theme="dark"]` and, for auto, under `prefers-color-scheme: dark` with `:root:not([data-theme="light"])`. Components must use the tokens, not their own `prefers-color-scheme` queries, or they ignore the switch.
- Breadcrumbs: every page except the home page starts with `src/components/Breadcrumbs.astro` (Start › … › current page), right before its `h1`; new page types must add it too.
- Pages: `src/pages/index.astro` is the home page: a centred hero (headline, three USPs as a check-marked list instead of a lede paragraph, the main call to action "Explore the trails" to `/trails/` and beside it the outlined secondary "Help me choose" to `/trails/guide/`), a strip of totals (they count up from 0 once the strip is first on screen, 1.2 s ease-out, from an inline script right after it so the final numbers never flash first; screen readers get only the final value; nothing moves with reduced motion or without JavaScript), a featured trail (the first trail for now; countries only, no regions, like the search cards) with a mini elevation profile and surface bar from its derived data, what every trail page offers, the data sources, and all trails as cards. `src/pages/trails/index.astro` is the search page (centred h1 and lede): `summarize()` in `src/lib/trails.ts` builds a compact record per trail (with the trail's derived data: season, water rating, surface shares, a coarse elevation profile, for `src/components/TrailList.svelte` (`client:load`), which filters and sorts in the browser (no text search). Filters sit in a sidebar (a full-screen panel behind a "Filters" button below 900 px), grouped by planning question: months (pills; season includes any), walking days (a two-thumb slider; the trail's days range must overlap), highest SAC grade (slider, last stop "Any"; once a grade is set, ungraded trails drop out), continents and countries (several at once, any of them; `toggleWhere()` keeps a continent and its own countries from being chosen together: a continent covers its countries, which show as included, and picking one of them narrows the choice to it; `where=Germany,Italy`), sleeping categories (pills; all of them), wild camping (its own group, segmented), longest stretch without drinking water (slider in km), share of natural ground (slider). Sliders are `src/components/Range.svelte` (native range inputs over fixed stops; two stacked for a range; no fill while a slider filters nothing), each with its setting in words beside the group title. Ordered scales get sliders; unordered choices keep pills. "Clear all" is always in the layout, only hidden, so it doesn't shift the filters; the sidebar's focus rings stay inside the column. The sidebar scrolls with the page (no sticky inner scroll box: its scrollbar came and went and shifted the filters), and the filters show no hint lines: each group's label is an Explain term with the details (SAC scale, sleeping categories, water levels, surface key) in its popover. Every filter is a URL parameter (shareable) and shows as a removable chip above the results. No single click leads from some results to none: a pill or segmented button that would leave no trail with the other filters is dimmed and disabled (with a tooltip; one that is on never is, so it can be undone), and a slider marks the stops that would leave none as a dashed track (`live`/`liveLo` in `Range.svelte`) and its thumb won't move onto them. Result cards show the countries (no regions), figures, water and wild camping status (shape plus word), sleeping, a season strip, and the elevation profile on one height scale for all trails (`eleRange`, so profiles compare honestly) with a surface share bar. Both pages ask search engines not to index, cache or quote them (`<meta name="robots" content="noindex, …">` via Base's `personal`) and reserve text and data mining (`tdm-reservation`, against AI training); `public/robots.txt` keeps known AI crawlers off them but doesn't block search engines there (they must fetch a page to see its noindex); the footer links to them are `rel="nofollow"`. The privacy policy lists every third party the site loads (today GitHub Pages, OpenFreeMap and AWS (elevation tiles); fonts and scripts are self-hosted): update it whenever the site starts loading something new (fonts, analytics, ads, embeds). `src/layouts/Base.astro`: header (logo and theme switch only, no navigation links), footer and the design tokens (warm palette, serif headings) with dark mode overrides; text colours were checked for WCAG AA contrast in both modes, so check new ones too.

## Ground rules

- Only official trails: a route designated or maintained by a government body or a recognised trail association. Unofficial routes (for example the Hayduke Trail) are out of scope unless docs/scope.md says otherwise.
- Every figure on a page must come from a source listed in the trail's record (or, for sources used across trails, in docs/data-sources.md), with its licence and retrieval date. Check a source's licence before using it: official GPX tracks are often copyrighted, and OpenStreetMap data requires ODbL attribution.
- Trail lengths, elevation gain and similar numbers differ between sources. Show which source a number comes from rather than silently picking one, and never mix them in one figure.
