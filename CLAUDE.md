# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

huckepack is a website that collects and visualises data about official long-distance hiking trails worldwide, focused on well-known thru-hiking routes: one page per trail plus comparisons across trails. docs/scope.md holds decisions and open questions (record new decisions there), docs/data-sources.md lists sources with their licences, docs/roadmap.md ranks candidate trails and features (update it when one is built).

## Commands

```bash
npm install          # once (inside Claude Code's sandbox: npm_config_cache="$TMPDIR/npm-cache" npm install)
npm run dev          # local site at http://localhost:4321; runs detached (npx astro dev status | logs | stop)
                     # before starting: lsof -nP -iTCP:4321 -sTCP:LISTEN; if one is running, reuse it (it reloads
                     # on file changes). Claude Code's sandbox can't stop a detached server; the user has to.
                     # After adding an npm dependency, the server must be restarted: a running server serves
                     # the new package as "504 outdated dependency" and the page breaks.
npm run build        # dist/: the static site; fails if a trail file doesn't match the schema
npm run check        # type check (Astro, Svelte, TypeScript)

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # once (PyYAML, truststore)
.venv/bin/python -m pipeline.routes <slug>             # map line: OSM ways matched to the stages' tracks (cached in data/raw/<slug>/)
.venv/bin/python -m pipeline.routes <slug> --refresh   # download tracks and OSM ways again
.venv/bin/python -m pipeline.water <slug>              # drinking water and springs near the route (after routes)
.venv/bin/python -m pipeline.access <slug>             # road distance from the record's travel hubs to the start (OSRM)
```

Inside Claude Code's sandbox, pip needs `PIP_CACHE_DIR="$TMPDIR/pip-cache"`. Python downloads verify certificates through the OS trust store (`truststore`); never disable verification.

## Architecture

- `data/trails/<slug>.yaml`: the trail database, one file per trail; the file name is the URL slug. `src/content.config.ts` is its schema (Zod): every figure names a `source` id from the trail's `sources`, and the build fails on an unknown id. A source's `retrieved: null` means its figures are not yet checked; the page says "not yet verified". `status: draft` trails are built and badged as drafts (no release mechanism yet). `notes` holds discrepancies between sources and open questions; they are for us, not shown on the page.
- `src/lib/trails.ts`: derived figures, never stored: totals from the main stages (`kind: main`; approaches and variants are excluded), averages per day (only when days and stages share a source), and the SAC grade for filtering (stated, or converted from CAI with `CAI_TO_SAC`). Each result carries its source.
- `pipeline/`: Python, downloads and processes source data into `data/raw/<trail>/` (committed cache, with `manifest.json` retrieval times) and writes derived data. The site build never downloads. `pipeline/routes.py` builds `public/routes/<slug>.geojson`: one simplified LineString per stage (number, kind, coverage) of OpenStreetMap geometry, matched by `pipeline/osm.py` to the stage's `track` (GPX). The matcher fetches OSM ways within 200 m of the track (Overpass, cached as `osm-stage-*.json`) and takes the cheapest path from start to end, where a way costs its length × (1 + (distance from track / 15 m)²). The GPX only guides the choice; none of its geometry is published. The printed report flags stages where less than 95% of the track is within 30 m of the result: usually OSM is missing a path there; record it in the trail's `notes`.
- `data/derived/<slug>.json`: data the pipeline derives for a trail, never edited by hand; the `derived` collection in `src/content.config.ts`. `water` (from `pipeline/water.py`): OSM drinking water (amenity=drinking_water/water_point, man_made=water_tap, springs tagged drinking_water=yes) and other springs within 250 m of the route, each with its stage and km along the main route (measured on the map line), counts per stage, and the longest stretches without drinking water / any water. Its `source` must be an id in the trail's `sources` (`osm`). `access` (from `pipeline/access.py`): for each hub in the record's `access` list (the nearest major hubs only: a main railway station and international airports, no small local stations; chosen by hand, coordinates from OSM; no notes), the road distance and driving time to the start from the public OSRM demo server (light use only; source `osrm`) and the straight-line distance.
- Sleeping: records list types (`SLEEPING_TYPES`); pages and the search filter group them into `SLEEPING_CATEGORIES` in `src/lib/trails.ts`, in this order: wild camping (from the record's `wildCamping`, no types), camping, huts, hostels, rooms. Card headlines must fit one line on desktop (each section's cards share one row from 900 px), so keep category labels short. Every type belongs to exactly one category; add new types to a category there. `SLEEPING_LABELS` are generic and in sentence case; local names (rifugi, refugios) belong in a trail's own text.
- Water: the page shows cards: availability (`WATER_LEVELS`: frequent ≤ 10 km, regular ≤ 20 km, scarce beyond, by the longest stretch without drinking water), drinking water points, springs, and the longest dry stretch.
- Icons: `src/components/Icon.astro` inlines Lucide icons (`lucide-static`, ISC) as SVG at build time, decorative unless given a `label`. Used where they speed up scanning: key-figure labels, sleeping and water cards (coloured by the card's tone), travel hubs (train/plane, labelled), home page features. Not on trail cards, filters or tables. New icons: import the SVG in `Icon.astro` and add it to `ICONS`.
- Section and card styling on the trail page: sleeping and water use the shared `.cards` grid: the icon sits inline before the card name; dashed outline for categories the trail lacks. Key-figure icons sit inline before the label. The wild camping rule is a plain paragraph below the sleeping cards. Stages are a timeline (numbered dots on a line; approach and variant dashed) with figures in fixed-width columns and an icon legend above. Location reads: start, finish, travel hubs (left column on desktop), then country, regions, protected areas, waymarking, managed by (right column). Stages put route and figures on one line from 820 px. Icons in labels and card names are top-aligned to the first line. Keep the page compact: sections 36 px apart, map 11:5 on desktop. The map shows only the route and termini (water points are counted, not drawn). Cards that state a status are colour-coded with the status tokens in `Base.astro` (`--good`/`--fair`/`--poor` and their `-soft` tints: moss, ochre, brick; checked for WCAG AA in both modes) via `tone-good|fair|poor`: sleeping categories present = good; wild camping allowed/restricted/prohibited = good/fair/poor; water availability and the longest dry stretch frequent/regular/scarce = good/fair/poor. Plain counts stay neutral, and the text always states the status, so colour is never the only cue.
- Explanations: `src/components/Explain.astro` is a "?" button with a popover (`popover` attribute, no JavaScript; closes with Esc, a click outside or Close), placed right after a label; the slot holds the text. Used for the SAC scale on the difficulty key figure (`SAC_SCALE`) and for every sleeping and water card (sleeping texts are the `hint` of each `SLEEPING_CATEGORIES` entry). Cards carry no visible hint line, only headline and value.
- Trail page: an on-page navigation (sticky) links to the sections the trail has. The page shows no footnote markers: figures are not linked to their source on the page; the Sources section lists every source of the record (licence, retrieval date). The record still names a source for every figure.
- Maps: `src/components/TrailMap.svelte` (MapLibre GL, `client:visible`) draws the route over the OpenFreeMap "liberty" basemap (OpenStreetMap data, no API key); main stages solid, approaches and variants dashed, start and end as dots. The trail page passes the route only if `route` is set and the file exists; otherwise the map shows just the termini. The attribution names the route's source.
- `route.publishable: false` means the geometry's licence doesn't allow republishing it (official GPX tracks usually don't). Such routes are fine for local drafts but must not be deployed: replace them with OSM-derived geometry first. `data/raw/` may hold such files too; never copy them into `public/` other than through the pipeline.
- Pages: `src/pages/index.astro` is the home page (what the site offers, trail cards). `src/pages/trails/index.astro` is the search page: `summarize()` in `src/lib/trails.ts` builds a compact record per trail for `src/components/TrailList.svelte` (`client:load`), which searches, filters and sorts in the browser. `src/pages/trails/[slug].astro`: one prerendered page per trail. `src/layouts/Base.astro`: header, footer and the design tokens (warm palette, serif headings) with dark mode overrides; text colours were checked for WCAG AA contrast in both modes, so check new ones too.
- Keep pages prerendered: only interactive parts (filters, maps, charts) become Svelte islands.
- Package versions are pinned exactly. TypeScript stays on 6.x until `@astrojs/svelte` and `@astrojs/check` support 7.

## Ground rules

- Only official trails: a route designated or maintained by a government body or a recognised trail association. Unofficial routes (for example the Hayduke Trail) are out of scope unless docs/scope.md says otherwise.
- Every figure on a page must come from a source listed in the trail's record (or, for sources used across trails, in docs/data-sources.md), with its licence and retrieval date. Check a source's licence before using it: official GPX tracks are often copyrighted, and OpenStreetMap data requires ODbL attribution.
- Trail lengths, elevation gain and similar numbers differ between sources. Show which source a number comes from rather than silently picking one, and never mix them in one figure.
